FormationRescue (AI-Powered Dance Formation Reblocking)

1. Solves one problem extremely well: FormationRescue helps dance teams automatically reorganize their formations when a dancer becomes unavailable due to injury, illness, scheduling conflicts, or other circumstances. Normally, captains must manually adjust multiple formations, reassign positions, and modify transitions, often forcing dancers to relearn choreography shortly before a performance. FormationRescue solves this specific problem by generating revised formations that minimize position changes, preserve choreography directions, and reduce the amount of relearning required across the entire routine.

2. Target customers or direct access: The primary target customers are collegiate dance teams, competitive dance studios, high school dance teams, and choreographers who regularly manage formations involving multiple performers. The initial target market is collegiate dance teams, particularly Bollywood fusion and other competitive dance teams. We have direct access to potential users through our involvement with dance teams at UVA and connections with other collegiate dance teams. This allows us to interview captains, gather feedback, and test the product using realistic formation scenarios. The product could eventually expand to cheerleading teams, marching bands, theater productions, and other performance groups.

3. Familiar infrastructure: The project uses concepts and technologies we are familiar with or can learn within six weeks, including Python, JavaScript, React, basic web development, coordinate geometry, graph algorithms, and optimization techniques. We can represent dancers and their formations as coordinates on a two-dimensional grid and use optimization algorithms to minimize position changes, movement distances, and choreography direction switches. An LLM API will support creative formation generation and interpretation of choreographer preferences, while deterministic algorithms will validate the proposed formations.

4. Reimagines the problem space: FormationRescue transforms traditional dance formation software from a manual visualization and editing tool into an AI-powered choreography recovery system. Existing applications such as Sway and Choreographic primarily help teams design and visualize formations, while other tools offer certain reblocking capabilities. FormationRescue focuses specifically on automatically repairing an entire routine while minimizing disruption to choreography. When a dancer becomes unavailable, the system considers all affected formations together rather than requiring the captain to individually redesign each one. It also accounts for mirrored choreography, where dancers may perform left-facing or right-facing versions of the same movements. By prioritizing solutions that preserve each dancer's learned choreography direction, FormationRescue aims to reduce unnecessary relearning while maintaining formation symmetry, spacing, and feasible transitions.

5. LLM/Generative model is core: The LLM is responsible for generating creative alternative formation arrangements based on the original choreography, the unavailable dancer, and the captain's artistic preferences. For example, a captain might request that the system preserve a V-shaped formation, keep a featured dancer in the center, or avoid switching dancers between left-facing and right-facing choreography. The LLM interprets these requirements and proposes revised layouts that preserve the original artistic intent. An optimization algorithm then assigns dancers to positions while minimizing disruption across the routine. This combination allows the system to generate creative solutions while accounting for mathematical constraints. Unlike a simple LLM call, FormationRescue must evaluate coordinated changes across multiple formations and verify whether the resulting positions and transitions are feasible.

6. Validation Guardrail: No LLM-generated formation arrangement is presented as an approved solution without passing through a deterministic validator. The validator checks that every available dancer has exactly one assigned position, no unavailable dancers remain in the routine, dancers remain within stage boundaries, and minimum spacing requirements are satisfied. It also checks locked positions, choreography direction restrictions, and whether transitions are feasible within the assigned musical counts under the MVP's simplified movement model. The system evaluates proposed changes using metrics such as movement distance, number of reassigned positions, and number of choreography direction switches. Invalid formations are rejected rather than presented as executable solutions. Physical safety and complex choreography movements would still require review by the dance captain.

7. Self-Correction Loop: When the validator identifies an issue, such as dancers positioned too close together, an excessive travel distance, an impossible transition within the assigned counts, or a violation of a locked choreography direction, the system automatically sends the specific validation error back to the LLM. The LLM then generates a revised formation that attempts to resolve the conflict while preserving the original artistic requirements. The optimization algorithm reevaluates the dancer assignments, and the validator checks the updated arrangement. This process repeats for a limited number of attempts until a valid solution is found. If the constraints cannot be satisfied within the search limits, the system informs the captain which requirements are conflicting or unresolved instead of presenting an invalid formation.

8. Deployability: FormationRescue can be deployed as a web-based application using React for the frontend, Python with FastAPI for the backend, an LLM API for generating formation alternatives, and optimization algorithms for assigning dancers and validating transitions. For a six-week MVP, users will be able to create or enter a routine containing approximately 10–16 dancers and 5–8 formations, identify an unavailable dancer, specify choreography directions and locked positions, and automatically generate revised formations. The application will display before-and-after formation diagrams, highlight which dancers have changed positions or choreography directions, and provide a summary of the changes required. The MVP will focus on two-dimensional formations, simplified movement constraints, and single-dancer absences, with more complex choreography analysis and multiple simultaneous absences reserved for future development.
